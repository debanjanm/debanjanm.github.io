01 Approach

Statistical rigor, applied to systems that ship

I build agentic AI platforms at Standard Chartered GBS — multi-agent orchestration, retrieval, and fine-tuning infrastructure for compliance work, where every answer has to be traceable and every agent has to be governable.

The statistics training shows up in how I evaluate. A single train/test split that flatters a model is not a result; an accuracy number without an error bar is not evidence. Platforms · 2021 — Present

Multi-tenant agent governance backend

2025 — Present
Django · LangGraph · shared services layer · DDD / clean architecture

A shared backend that standardizes authentication, guardrails, retrieval, and audit logging across a family of compliance agents. Rather than each agent team reimplementing governance, the framework provides it — so a new agent inherits compliance controls by construction instead of by review. Built from scratch and led its domain-driven, clean-architecture migration with a two-person engineering pod.

Decision

In a regulated institution, audit logging and guardrails aren't per-team implementation details — they're a compliance surface. Centralizing them into a framework layer trades some team autonomy for a property that matters more here: you can answer "what did this agent do, and was it allowed to?" uniformly, for every agent, without auditing each one separately.

Multi-agent RAG platform for compliance review

2025 — Present
LangGraph multi-agent orchestration · jurisdiction-scoped retrieval · auditable answers

Built on the governance framework above. Compliance analysts previously ran a two-to-three day manual triage to answer a policy question; the platform returns a same-day, jurisdiction-scoped answer with its sources attached. Retrieval is constrained by jurisdiction rather than filtered after the fact, so an answer can never be assembled from documents that don't apply to the asking market.

Decision

Auditability had to be an output, not a log. An answer that a human can't trace back to a source is worthless in compliance review regardless of how good it reads, so citations are part of the response contract — the system would rather return less than return something unattributable.

~60–75% rated positively across internal evaluation batches

Regulatory impact analysis engine

2025 — Present
Two-stage reasoning · recall-weighted thresholds · concurrency & timeout budgets

An agent that reads incoming regulatory circulars and flags whether they affect existing bank policies. The costs here are asymmetric: a missed impact is a compliance exposure, a false alarm is an analyst's afternoon. The system is tuned accordingly — deliberately biased toward recall, accepting more false positives to drive missed impacts toward zero.

Decision

Most circular sections don't touch policy at all, so spending a full reasoning pass on every section is waste. A cheap first stage discards clearly non-impacting sections and the expensive reasoning runs only on candidates — roughly half the LLM calls, with the recall bias preserved because the cheap stage is tuned to over-admit rather than over-reject.

50% fewer LLM calls on non-impacting sections

Internal LLM fine-tuning platform

2024 — 2025
QLoRA · Mistral-7B-Instruct · 4-bit NF4 quantization · Flash Attention 2 · config-driven pipeline

An end-to-end fine-tuning platform covering data preparation through inference, driven by configuration rather than notebooks. Quantization and attention optimizations were the difference between fine-tuning being an occasional event and a routine one on the hardware actually available.

Decision

Config-driven over notebook-driven, because the point of a platform is comparability. A tuning run you can't reproduce or diff against the previous one isn't an experiment — it's an anecdote. Every run is declared by a config file that is itself the record of what was tried.

3x training speed10% memory reduction4% hit-rate gain10% BLEU/ROUGE

Multi-strategy entity extraction framework

2021 — 2024
4-layer cascade: regex · keyword · lookup · ontology · config-driven

A configurable extraction engine for financial documents, layering deterministic strategies ahead of learned ones. Deployed across four release phases; the deterministic layers resolve what they can, and only genuinely ambiguous fields reach the model. Paired with extending a sequence-tagging NER model (BERT + BiLSTM + Attention + CRF) into the document pipeline.

Decision

A layered cascade rather than one model end to end. When a regex or an ontology lookup can settle a field, it does so cheaply, deterministically, and — critically for document review — explainably. The model is reserved for what the deterministic layers genuinely can't resolve, which keeps both cost and the unexplainable surface area small.

50K+ documents/monthmanual entry 40h → 4h per 1K documents
